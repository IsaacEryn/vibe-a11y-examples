《바이브 코딩, 접근성까지 부탁해》 실습 데모

책에서 다루는 접근성 문제를 직접 겪어보는 페이지들입니다. 마우스를 치우고 Tab과 Enter로, 가능하면 스크린리더로도 사용해보세요.

일러두기 — '나쁜 예' 페이지는 접근성 문제를 체험하기 위해 의도적으로 잘못 만든 교보재입니다. 실제 서비스에서 그대로 쓰면 안 됩니다.

바로 쓰는 자료

  • 접근성 기본 규칙 세트 복사용 AI 규칙 파일에 붙여 넣는 8장의 규칙
  • 복사해서 쓰는 프롬프트 모음 복사용 본문에 등장하는 프롬프트 전문

장별 체험 데모

나쁜 예 문제를 겪어보는 화면 좋은 예 같은 화면을 고친 것 비교 둘을 나란히 놓은 것

5장 — AI에게 무엇을 만들지 제대로 알려주자

  • 막연한 요청과 조건이 담긴 요청비교

8장 — 접근성 요구사항을 AI의 기본 규칙으로

  • 규칙 파일이 있을 때와 없을 때비교

9장 — 버튼처럼 생겼는데 버튼이 아니다

  • 가짜 버튼 체험하기나쁜 예
  • 진짜 버튼 체험하기좋은 예
  • 두 버튼 나란히 보기비교

10장 — 이미지에 alt만 넣으면 끝일까?

  • 이미지를 껐을 때 남는 것비교

11장 — 예쁜 색인데 글자가 보이지 않는다

  • 색을 걷어낸 화면비교

12장 — 마우스를 치워보자

  • 포커스가 보이지 않는 화면나쁜 예
  • 포커스가 보이는 화면좋은 예

13장 — 입력하다 길을 잃지 않게 하자

  • 이름표가 사라지는 폼비교
  • 오류 메시지 비교비교

14장 — 모달을 열었더니 키보드가 사라졌다

  • 반쪽짜리 모달나쁜 예
  • 제대로 만든 모달좋은 예

15장 — 모바일에서는 또 다르다

  • 확대가 막힌 화면나쁜 예
  • 확대가 되는 화면좋은 예
  • 드래그 별점과 눌러서도 되는 별점비교

24장 — 아직 시작하지 않았다면

  • 실습으로 만든 랜딩 페이지 완성본완성본

지금은 다섯 개 장의 데모가 있습니다. 나머지 장은 책의 진행에 맞춰 하나씩 추가하고 있습니다. 비어 있는 장 번호는 아직 만들지 않았다는 뜻입니다.

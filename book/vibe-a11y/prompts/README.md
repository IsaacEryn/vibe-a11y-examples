# 복사해서 쓰는 프롬프트 모음

《바이브 코딩, 접근성까지 부탁해》 본문에 등장하는 프롬프트들입니다.
그대로 복사해 쓰되, `[대괄호]` 부분은 프로젝트에 맞게 바꿔주세요.
집필 진행에 따라 장별로 추가됩니다.

## 4장 — 프로젝트 시작 선언

```text
지금부터 이 프로젝트의 모든 UI 작업에 적용할 기준을 알려줄게.
- 목표: 키보드만 쓰는 사용자와 스크린리더 사용자를 포함해 누구나 전 기능을 쓸 수 있는 웹.
  WCAG 2.2 AA(한국 기준 KWCAG 2.2)를 준수한다.
- 항상 지킬 것: 시맨틱 HTML 우선, 모든 이미지에 alt, 모든 입력 필드에 label,
  명도 대비 4.5:1 이상, 색만으로 정보 전달 금지, 포커스 표시 유지.
- UI 코드를 만들 때마다, 적용한 접근성 처리를 코드 아래에 목록으로 보고해줘.
이 기준을 이해했으면 요약해서 확인해줘.
```

## 8장 — 가짜 버튼 일괄 수정

```text
이 프로젝트에서 클릭 이벤트가 달린 div와 span을 전부 찾아서 시맨틱 요소로 교체해줘.
- 동작을 실행하는 것은 <button type="button">으로, 페이지를 이동하는 것은 <a href>로 바꿔줘.
- 카드형 UI는 내부 제목을 링크로 만들고 클릭 영역만 카드 전체로 확장해줘.
- role="button"이나 tabindex, onkeydown으로 버튼을 흉내 내는 방식은 쓰지 마.
- 기존 클래스와 스타일은 그대로 유지하고, 필요하면 버튼의 브라우저 기본 스타일(테두리·배경)만 초기화해줘.
- 바꾼 요소 목록과 각각 버튼/링크 중 무엇으로 바꿨는지, 판단 이유를 함께 보여줘.
```

## 8장 — 수정 검증

```text
방금 수정한 파일에서 클릭 가능한 요소를 전부 나열하고, 각 요소에 대해 다음을 표로 정리해줘:
① 사용한 HTML 요소 ② Tab으로 포커스 가능한지 ③ Enter/Space로 동작하는지
④ 스크린리더에 어떤 역할로 읽히는지.
하나라도 충족하지 못하는 요소가 있으면 그 이유와 수정안을 제시해줘.
```

## 9장 — 이미지 대체 텍스트 전수 점검

```text
이 프로젝트의 모든 <img>(및 배경이미지로 정보를 전달하는 요소)를 찾아 표로 정리해줘:
① 파일/위치 ② 분류(정보/기능/장식) ③ 현재 alt ④ 제안 alt ⑤ 판단 근거.
규칙:
- 장식 이미지는 alt=""(빈 값)로. alt 속성 생략은 금지.
- 기능 이미지(링크·버튼 안)는 생김새가 아니라 동작/목적지를 설명.
- 파일명, "이미지", "사진" 같은 무의미한 값 금지.
- 이미지 안에 글자가 있으면 그 글자를 alt에 포함하고, 실제 텍스트로 대체할 수 있는지 별도 표시.
확신이 없는 항목은 "사람 확인 필요"로 표시해줘.
```

## 10장 — 색 대비 일괄 수정

```text
이 프로젝트의 CSS에서 텍스트/배경 색 조합을 전부 추출해서 표로 만들어줘:
① 사용 위치 ② 전경/배경 색상값 ③ 대비 비율 ④ 기준(본문 4.5:1, 큰 텍스트·UI 요소 3:1) 통과 여부.
미달 조합에는 수정안을 제시하되:
- 색상(hue)은 유지하고 명도만 조정해서 브랜드 색 계열을 지켜줘.
- 그라데이션·이미지 배경 위 텍스트는 가장 불리한 지점 기준으로 판단하고,
  필요하면 텍스트 뒤에 반투명 배경층을 제안해줘.
- 색만으로 상태를 구분하는 UI(상태 점, 차트 범례, 오류 표시)를 찾아
  아이콘·텍스트·무늬 병행안을 함께 제시해줘.
```

## 11장 — 키보드 접근성 일괄 점검·수정

```text
이 프로젝트에서 다음을 찾아서 고쳐줘:
1. outline: none 등 포커스 표시를 제거하는 CSS를 전부 찾아 제거하고,
   :focus-visible 기반의 포커스 링(브랜드 색, 대비 3:1 이상)으로 교체해줘.
2. 양수 tabindex를 전부 찾아서, DOM 순서 조정으로 대체하는 방안을 제시해줘.
3. CSS(order, position)로 시각 순서와 DOM 순서가 어긋난 구간을 찾아 보고해줘.
4. Tab으로 도달할 수 없는 조작 요소, 빠져나올 수 없는 위젯이 있는지 점검해줘.
각 항목의 변경 내역을 파일별로 정리해서 보여줘.
```

## 12장 — 폼 접근성 전수 점검·수정

```text
이 프로젝트의 모든 폼을 찾아 필드별 표로 점검하고 수정해줘:
① 필드 ② label 연결 여부(for/id) ③ placeholder를 label 대신 쓰는지 ④ 필수 표시 방식
⑤ autocomplete 적용 ⑥ 오류 메시지의 위치·연결(aria-describedby)·내용.
수정 규칙:
- placeholder만 있는 필드는 보이는 label을 추가하고, placeholder는 형식 예시로만 남겨줘.
- 오류 메시지는 필드 곁에 표시하고 aria-describedby로 연결, 제출 시 첫 오류 필드로 포커스 이동,
  기존 입력값 보존.
- 필수 표시는 색·별표 단독 금지, required 속성과 텍스트 병행.
- 글자 판독형 CAPTCHA가 있으면 대체 인증 방식을 제안해줘.
변경 전/후 코드를 필드별로 보여줘.
```

## 13장 — 모달 전수 점검·교체

```text
이 프로젝트에서 모달·팝업·오버레이 구현을 전부 찾아 점검하고 수정해줘.
- 우선 네이티브 <dialog> + showModal()로 교체 가능한 것은 교체해줘. 기존 디자인은 유지.
- 교체가 어려운 것은 다음 체크리스트로 점검·보완해줘: 열릴 때 포커스 인, Tab/Shift+Tab 순환,
  ESC 닫기, 닫힐 때 포커스 복귀, role="dialog"·aria-modal·aria-labelledby, 배경 inert 처리.
- 닫기 버튼에 접근 가능한 이름("닫기")이 있는지 확인해줘.
- 모달별 점검 결과를 체크리스트 표로 보고해줘.
```

## 14장 — 모바일 접근성 일괄 점검·수정

```text
이 프로젝트를 모바일 접근성 관점에서 점검하고 수정해줘:
1. 뷰포트 메타태그에서 user-scalable=no, maximum-scale 제한을 찾아 제거해줘.
2. 화면 방향을 고정하는 설정·CSS·스크립트가 있으면 보고하고 제거를 제안해줘.
3. 드래그·스와이프·길게 누르기·흔들기로만 조작되는 기능을 전부 나열하고,
   각각에 단순 탭 대체 수단을 추가해줘.
4. 호버에만 의존해 표시되는 콘텐츠(툴팁, 드롭다운, 버튼)를 찾아
   터치·포커스로도 접근 가능하게 바꿔줘.
5. 터치 대상이 44×44px 미만이거나 간격이 부족한 곳을 보고해줘.
항목별 변경 내역을 표로 정리해줘.
```

## 15장 — 접근성 현황 진단과 수리 계획

```text
이 프로젝트 전체를 접근성 관점에서 진단하고 수리 계획을 세워줘.
1. 유형별로 문제를 찾아줘: 가짜 버튼, 무의미한 alt, 색 대비, 키보드(포커스 표시·순서·함정),
   폼(label·오류), 모달, 모바일(뷰포트·제스처).
2. 각 문제에 다음을 표기해줘: 위치 / 공통 컴포넌트 여부 / 심각도(차단·불편·미관) /
   핵심 동선(가입·결제 등) 해당 여부.
3. "핵심 동선 × 공통 컴포넌트 × 차단"이 겹치는 것부터 정렬한 수리 계획을 만들어줘.
   한 번에 한 컴포넌트씩, 각 단계의 예상 변경 범위를 함께.
지금은 진단과 계획만. 수정은 내가 승인한 뒤 단계별로 진행하자.
```

## 18장 — 컴포넌트 접근성 리뷰

```text
너는 웹 접근성 전문 코드 리뷰어야. 아래 컴포넌트를 WCAG 2.2 AA 기준으로 리뷰해줘.
출력 형식:
| 심각도(차단/불편/미관) | 위치 | 문제 | 근거 기준 | 왜 문제인가(영향받는 사용자) | 수정안 |
규칙:
- 수정안은 네이티브 HTML 우선, ARIA는 필요한 경우에만.
- 문제가 없다고 판단한 영역도 "확인함"으로 표시해줘 (키보드, 이름, 대비, 구조).
- 확신이 없는 항목은 "사람 확인 필요"로 분리해줘.
```

## 18장 — 자동 검사 결과 기반 일괄 수정

```text
아래는 자동 접근성 검사 결과야. [검사 결과 붙여넣기]
1. 위반들을 같은 원인끼리 묶고, 원인별로 근본 수정안을 제시해줘 (증상 단위가 아니라 원인 단위로).
2. 공통 컴포넌트에서 발생한 것과 개별 페이지 문제를 구분해줘.
3. 내가 승인하면 원인 하나씩 수정하고, 수정마다 어떤 위반들이 해소되는지 명시해줘.
4. 전부 끝나면 재검사에서 확인해야 할 항목 목록을 만들어줘.
```

## 19장 — 검사 대상 목록 만들기

```text
이 프로젝트의 라우트(페이지) 구조를 분석해서 접근성 검사 대상 목록을 만들어줘.
1. 페이지를 템플릿 유형별로 분류해줘.
2. 다음 다섯 그룹으로 대표 표본을 제안해줘: 공통 페이지 / 핵심 과업 전 과정
   (과업을 지정해줄게: [핵심 과업]) / 유형별 대표(콘텐츠가 복잡한 개체 기준) /
   상태·변형(로그인 전후, 빈/오류 상태, 모바일) / 무작위 2~3개.
3. 표로 정리해줘: 유형 / URL / 검사할 상태 / 비고.
```

## 20장 — 접근성 검사 자동화 설정

```text
이 프로젝트에 자동 접근성 검사를 설정해줘.
1. axe 기반 검사를 다음 페이지들에 대해 실행하는 테스트를 만들어줘: [검사 대상 목록]
2. 배포 전에 이 테스트가 자동 실행되고, 새로운 위반이 발견되면 배포가 중단되게 해줘.
3. 기존 위반은 기준선(baseline)으로 기록해두고, 기준선보다 늘어나는 것만 실패로 처리해줘.
4. 검사 결과가 위반별로 어떤 페이지·요소에서 나왔는지 보고서로 남게 해줘.
설정 후, 일부러 위반(alt 없는 img)을 하나 넣어 검사가 실제로 실패하는지 확인해줘.
```
